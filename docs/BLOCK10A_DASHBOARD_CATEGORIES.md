## Implemented contracts

GET `/api/v1/workspaces/:wid/dashboard`: required currency/start/end, optional accountId/categoryId; one authorized snapshot for cash, categories, comparisons, balances, receivables, recent activity and portfolio. POST `/categories`: UUID id, name, kind (income/expense), icon, color. PATCH `/categories/:id`: expected updatedAt, name/icon/color; kind immutable. POST `/categories/:id/archive`: expected updatedAt; historical references retained. Existing GET categories adds metadata and optimistic timestamp. Existing transaction categorization protections remain authoritative.

## Implementation and financial boundaries — 26 November 2026

F05 Home, F06 Dashboard and F15 Categories now select persistent adapters only in `VITE_AUTH_MODE=api`. Demo components and their shared in-memory services remain intact. Both report screens use the same query and exact calculations. Workspace, currency (AUD/EUR/USD), inclusive UTC booking-date range, account and category filters form the query key. Changing scope clears dependent selectors. No mock identity can authorize this endpoint.

The report controller delegates strict input validation, repository reads and aggregation to separate modules. `summarizeCash` uses BigInt throughout; decimal strings carry minor units to React. Savings percentage is truncated toward zero to two decimal places and is unavailable without positive income. Six or fewer consecutive date buckets reconcile to the selected ledger. Split children replace the parent for category attribution; transfers and excluded rows contribute no ordinary income/expense. Recent activity shows whole parent amounts and explicitly warns that category slices may represent only part of a split parent.

Account balances are recorded opening balances plus included signed ledger movements through the selected end, including transfers. They are not bank-verified available funds. Balances are unavailable before the account opening date and for a category slice. Outstanding receivables use issued invoices in the issue-date/account/currency scope minus currently confirmed allocations, not a historical payment snapshot. Category filters do not allocate receivables. Investments reuse the existing weighted-average portfolio replay as of the end date across investment accounts in the workspace/currency; cash-account/category filters do not allocate holdings. Manual valuation dates are exposed. Missing or invalidated valuations stay null; investment movements do not post cash.

Category creation uses a caller-generated UUID for retry identity; a matching retry returns the existing record and a conflicting reuse fails. Metadata edit/archive requires the exact `updatedAt` version. Kind is immutable. Archive preserves historical references and blocks new assignments. No delete or restore operation was introduced. Owner/Editor can mutate; Viewer can read. Transaction assignment uses the established category-only endpoint and retains invoice-linked, split, transfer, archived-category and workspace protections. React invalidates workspace queries after successful changes and preserves errors for review.

## Security and query review

Every report and category command revalidates the session and active server-side workspace membership within `withActor`; the existing user/workspace locking order serializes membership changes and writes. Independent-connection category updates yield one success and one conflict with one audit entry. Session cookies, origin/header CSRF checks, authentication throttling and sanitized errors are inherited unchanged. Unknown fields, invalid IDs/currencies/dates, future end dates and ranges longer than 366 days are rejected. Foreign workspace/account/category references do not expose data. Revocation removes access to reports and categories. Query ownership is never taken from the request body.

The report uses one browser summary request and a fixed set of repository reads, including one grouped account-balance query rather than per-account queries. Cash history includes only the current and equally sized prior range; category/account/invoice collections fail above 10,000 records rather than silently truncating totals. Investment reads retain their existing bounds. There is no report pagination that could quietly omit financial totals. These are local bounded-query observations, not a production load test. Workspace locks and full portfolio replay may require optimization at scale.

## Remaining limitations

No AI, live banking, exchange rates, market feeds, automatic reconciliation, rule execution, background automation, production deployment or historical balance trend. Invoice receivables describe current allocations within an issue-date selection. Read-only summaries cannot prove bank completeness. API shell's demo workspace selector remains explicitly labeled and does not select or authorize the persistent workspace; page selectors do. Conversation history and new chat are unavailable in API mode. Other previously documented unsupported operations remain unsupported. Distributed rate limiting, production credentials/hosting, observability/load testing, broader browser/device coverage and independent visual approval remain future work. This block establishes local integration evidence, not production readiness. Block 10B was not started.
