IDs in path/body are untrusted. Every future repository operation must derive actor identity from a real session and scope all referenced records. Neither Prisma IDs nor the schema's composite FKs authorize a caller to read a workspace. Avoid leaking existence via inconsistent inaccessible-record responses. Domain GET/list operations need bounded pagination, documented sort order and precise filter semantics.

## Representation contracts

Frontend safe integer amounts map to BIGINT decimal strings in JSON, with explicit bounds checked before converting back to Number. Fractional invoice and investment fields remain decimal strings. Business dates are YYYY-MM-DD, event instants ISO UTC; schedules additionally carry a named timezone. Convert current fixture IDs to server UUIDs in an adapter, never by modifying existing frontend fixture records in this block.

Frontend `prepared-not-sent` maps to InvoiceDelivery `prepared`; stored invoice lifecycle remains draft/issued/cancelled and the server derives display status. Frontend duplicate `both` maps to `keep_both`, original/exclude to `use_original`/`exclude`. `pending-review` maps to automation `pending_review`, `in-app` to `in_app`. The schema preserves preferences without implying the UI implements translation, timezone scheduling or email delivery.

Opening balance is a dated stock, not period income. Confirmed received income is the transaction ledger; payment allocations describe use of an existing receipt. Imported duplicates remain candidates until reviewed; identical-looking real transactions can coexist. Portfolio distributions and capital movements remain separate from cash until a later explicit, uniquely reconciled linking contract is approved.

## Transaction and retry requirements

Use one database transaction for invoice header/items, payment/receipt/allocation, reviewed batch import, split replacement, paired transfers, workspace/owner creation and recurring run/draft creation. Respect deferred checks; do not issue these writes as unrelated requests and expect intermediate invalid states to persist. Database financial fences serialize covered workspace changes, with allocation conflicts verified on PostgreSQL 18.7 using separate connections at ReadCommitted and Serializable. All 31 live integration tests passed. Workload benchmarking and other concurrent command combinations remain pending.

Investment histories need service-level position locking/version checks and deterministic replay; this is not implemented by merely storing movements. Finalized-document immutability, normalized email input, invoice numbering allocation, accepted invitation identity, JSON shapes, manual override protection, file permissions and all authorization remain backend responsibilities. Retry deadlocks/serialization failures only around the complete idempotent command, after rechecking actor access and record versions. Never retry real delivery blindly without provider idempotency.
